pub struct FixedCapacityElements<Element, const CAPACITY: usize>
where
    Element: TrivialType,
{ /* private fields */ }
Expand description

Container for storing a number of elements limited by the specified fixed capacity.

See also FixedCapacityBytes and FixedCapacityString.

In contrast to VariableElements, which can store arbitrary number of elements and can change the capacity, this container has fixed predefined capacity and occupies it regardless of how many elements are actually stored inside. This might seem limiting but allows implementing TrivialType trait, enabling its use for fields in data structures that derive TrivialType themselves, which isn’t the case with VariableElements.

The length (the number of stored elements) is a little-endian u32 in the first 4 bytes, followed by zero bytes up to TrivialType::ALIGNMENT of elements if it is larger than 4 bytes, and CAPACITY elements after that. As a result, the container has the same alignment as elements and no padding, regardless of the alignment of elements.

CAPACITY must not exceed u32::MAX, and the size of the container must be smaller than 2^32.

Parsing rejects a length above CAPACITY, but doesn’t check the rest of the length prefix, which is set to zero bytes whenever the length is set. The unsafe methods of TrivialType that skip parsing can create an instance with a larger length: methods don’t panic then, but such an instance has no accessible elements and nothing can be appended to it until a valid length is set with Self::truncate() or Self::copy_from().

Elements beyond the length are not part of the value. Default and Self::try_from_slice() fill them with default elements, while Self::truncate() and Self::copy_from() leave them as they are, so bytes of instances with the same elements can differ. Parsing checks all CAPACITY elements, they are values of Element too.
